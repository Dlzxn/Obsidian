| Архитектура                                  | Плюсы                                                                             | Минусы                                                              | Примеры                                                           | Связь с DDD                                                                  |
| -------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Монолитная**                               | Простая разработка и деплой; легко тестировать маленький проект                   | Трудно масштабировать; изменения могут ломать всё                   | Django, Rails, старые корпоративные приложения                    | DDD тяжело внедрять, ограничено разделение контекстов                        |
| **Слойная (Layered / N-tier)**               | Чёткое разделение ответственности; легко тестировать слои                         | Может возникнуть сильная зависимость между слоями; иногда избыточно | Java EE, Spring MVC                                               | Хорошо работает с DDD: Domain слой + Application слой                        |
| **Чистая (Clean / Hexagonal / Onion)**       | Бизнес-логика в центре; независимость от фреймворков; тестируемость               | Много абстракций; сложнее на старте                                 | Приложения на Python, Java, .NET, где делают dependency inversion | DDD идеально ложится в Domain Layer                                          |
| **Микросервисы**                             | Масштабируемость; независимая разработка команд; лёгкий деплой отдельных сервисов | Сложность интеграции; распределённые транзакции; управление сетью   | Netflix, Uber, Amazon                                             | Каждый Bounded Context из DDD может быть отдельным микросервисом             |
| **Событийно-ориентированная (Event-Driven)** | Асинхронность; легко расширять систему; масштабируемость                          | Сложно отлаживать; нужно управлять очередями сообщений              | Kafka, RabbitMQ, системы обработки логов                          | Можно интегрировать DDD через публикацию событий агрегатов                   |
| **Сервис-ориентированная (SOA)**             | Интеграция разных систем; стандартизация сервисов                                 | Сложности с версионированием и интерфейсами                         | Корпоративные ERP, SAP                                            | DDD можно применять на уровне сервисов и bounded contexts                    |
| **Peer-to-Peer / распределённая**            | Масштабируемость без центрального сервера; отказоустойчивость                     | Сложнее согласовывать данные; безопасность критична                 | BitTorrent, Blockchain                                            | DDD трудно применять напрямую, но можно строить доменные модели внутри узлов |
